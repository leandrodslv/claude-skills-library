## Comment c'est rangé

```
00-Inbox/          capture brute, à trier — ne doit jamais s'accumuler
01-Projets/        études en cours (échéance + livrable attendu)
02-Domaines/       sujets permanents — une carte par domaine
03-Connaissances/  ce que la cellule sait, indépendamment des projets
04-Ressources/     méthodes, biais, benchmarks
05-Archives/       études terminées
_templates/        modèles de notes
```

**La distinction qui compte** : un projet se termine, un domaine jamais.
« Refonte de la page tarifaire » est un projet, « Tarification » est un domaine.

---

## Les deux chemins de lecture

**Par étude** — ouvre une étude dans `05-Archives/`, tu suis le pipeline dans
l'ordre : plan → questionnaire → guide → entretiens → synthèse → insights →
rapport.

**Par connaissance** — pars d'un domaine, tu vois ce qu'on sait, avec quel
niveau de confiance et sur combien d'études. Chaque connaissance renvoie aux
verbatims qui la fondent.

Le second chemin est celui qui fait gagner du temps : avant de lancer une
étude, on regarde ce qui est déjà su.

---

## Conventions

- Participants désignés par un identifiant (`#001`) — jamais de nom
- Verbatims **jamais** reformulés
- Une connaissance sans source est une opinion : chaque nugget cite ses études
- Une contradiction se documente, elle ne s'efface pas
- Une connaissance non reconfirmée depuis 12 mois passe en `a-reverifier`
